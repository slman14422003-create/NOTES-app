# أمان Firebase والتطبيق — قائمة الإعداد

## ما الذي يحمي ملاحظاتك فعلًا
1. **قواعد Firestore** (`firestore.rules`): كل مستخدم يصل إلى `users/{uid}/notes` الخاص به فقط، بشرط تسجيل الدخول عبر Google وبريد موثّق. لا مجموعات أخرى ولا قراءة لمستخدمين آخرين.
2. **حساب Google**: لا كلمات مرور تُخزَّن أو تُخمَّن، ولا حسابات مجهولة.
3. **التطبيق**: جلسة مشفّرة بـ Keystore، وقاعدة محلية مشفّرة، وكشف التعديل، وتشفير النصوص وقت البناء (تعمية فقط).

> لا يوجد تطبيق «غير قابل للاختراق». فحوص التطبيق ترفع كلفة الهجوم، أما حماية البيانات نفسها فتعتمد على القواعد أعلاه في الخادم. معرّفات Firebase (`apiKey`, `projectId`) ليست أسرارًا ولا يعتمد الأمان على إخفائها.

## خطوات Firebase / Google Cloud (مرة واحدة)
1. **Authentication ← Sign-in method**: فعّل **Google** فقط وعطّل غيره (Email/Password, Anonymous).
2. **Firestore ← Rules**: الصق `firestore.rules` ثم **Publish** (أو `firebase deploy --only firestore:rules`).
3. **تقييد مفتاح الـ API** (أهم خطوة): Google Cloud Console ← APIs & Services ← Credentials ← مفتاح الـ API:
   - Application restrictions ← **Android apps** ← أضف الحزمة `app.semo.notes` وبصمة **SHA-1** للمفتاح (`BD:99:E8:37:77:70:CE:69:A1:C2:CD:C0:3F:B7:79:59:A9:46:AA:9F`) (وبصمة نسخة debug إن استخدمتها).
   - API restrictions ← **Restrict key** ← اختر: *Identity Toolkit API*, *Token Service API*, *Cloud Firestore API*.
   التطبيق يرسل `X-Android-Package` و`X-Android-Cert` تلقائيًا لهذا الغرض.
4. **Billing ← Budgets & alerts**: ضع ميزانية وتنبيهًا حتى لو كان المشروع مجانيًا.
5. **اختبار القواعد**: Firestore ← Rules ← Rules Playground: جرّب قراءة `users/آخر-uid/notes/x` بحساب مختلف فيجب أن تُرفض.
6. **App Check** (اختياري): يتحقق من أن الطلبات من تطبيقك الأصلي. مزوّد Play Integrity يتطلب توزيعًا عبر Google Play، فلا يناسب APK يُوزَّع عبر GitHub، لذلك لم يُفعَّل.

## أسرار GitHub (Settings ← Secrets and variables ← Actions)
| السر | الاستخدام |
|---|---|
| `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD` | توقيع الـ APK (إلزامي) |
| `WEB_CLIENT_ID` | تسجيل الدخول بـ Google |
| `FIREBASE_API_KEY`, `FIREBASE_PROJECT_ID` | اختياري: بدل القيم الافتراضية في `app/build.gradle` |

بصمة شهادة التوقيع تُقرأ تلقائيًا من المفتاح أثناء البناء وتُدمج مشفّرة في التطبيق للتحقق من التوقيع عند التشغيل.

## ماذا يفعل التطبيق ضد التلاعب
- يرفض العمل (وإرسال أي طلب) إذا كان التوقيع ليس توقيعك، أو الـ APK قابلًا للتنقيح، أو يوجد مُنقِّح متصل (في نسخ release فقط).
- لا يتصل إلا عبر HTTPS ويثق بشهادات النظام فقط (شهادات يضيفها المستخدم لا تُقبل).
- المحرّر خاص ولا يفتحه تطبيق آخر، والمدخل العام الوحيد يمرّر نصًا محدودًا.
- النسخ الاحتياطي لأندرويد معطّل، وجلسة الدخول مشفّرة بمفتاح داخل Keystore، وعنوان/نص كل ملاحظة مشفّر في القاعدة المحلية.
- التحديثات: من أصول مستودعك فقط، ولا يُقبل إلا ملف أحدث وبنفس التوقيع.
- الإعدادات ← **حذف كل بياناتي**: يمسح السحابة والجهاز ويحاول حذف الحساب.

## حدود معروفة
- من يملك جهازًا مكسور الحماية (root) وأدوات حقن قادر نظريًا على تجاوز الفحوص المحلية، لكنه لن يصل إلى ملاحظات حساب آخر لأن القواعد في الخادم.
- ملاحظاتك في Firestore مشفّرة أثناء النقل وعند التخزين من Google، لكنها ليست مشفّرة من طرف إلى طرف.
